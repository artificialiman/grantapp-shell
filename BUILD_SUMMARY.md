## Key Design Decisions Implemented

### 1. Device-Bound Hard Lock
- **File:** `src/routes/api/bind-device/+server.ts`
- **Flow:** First device binds successfully. Second device gets 409 error (hard lock). Old device must be unlocked via admin.
- **Storage:** `device_bindings` table (1 row per student, max 1)
- **Invariant:** Binding only via server-side route using `SERVICE_ROLE_KEY` (never client-writable)

### 2. Premium Content Gate
- **File:** `src/routes/premium/+layout.server.ts`
- **Logic:** Redirects if session missing, expired, subscription inactive, or device mismatch
- **Redirect:** Server-side `throw redirect(303, '/login')` (no flash, no client-side navigation)
- **Invariant:** Single gate in one file, prevents "gate drift"

### 3. Device Tag Storage
- **File:** `src/lib/auth/deviceTag.ts`
- **Method:** Random UUID stored in `localStorage` (not fingerprinting)
- **Rationale:** Fingerprinting unreliable on iOS; server-side enforcement is the real security boundary
- **Behavior:** If localStorage wiped (iOS 7-day eviction), treated as new device

### 4. Offline PWA Support
- **Config:** `vite.config.ts` with `@vite-pwa/sveltekit`
- **Cache Strategies:**
  - **Cache-first:** `static/content/*` (question JSON, fonts)
  - **Network-first:** Premium hub, subscription status
  - **Never cache:** Auth endpoints (`/api/bind-device`, etc.)
- **Indicator:** Online/offline badge in navbar (`src/routes/+layout.svelte`)

### 5. No Hand-Written Service Worker
- **Tool:** Workbox (via `@vite-pwa/sveltekit` with `strategies: 'generateSW'`)
- **Rationale:** Workbox handles edge cases (partial responses, opaque responses, versioning) automatically
- **File:** Generated at build time, not checked into repo

### 6. Supabase Session Middleware
- **File:** `src/hooks.server.ts`
- **Purpose:** Runs on every request, loads session into `event.locals`
- **Usage:** Other `+layout.server.ts` and `+server.ts` files access session via `event.locals.getSession()`
