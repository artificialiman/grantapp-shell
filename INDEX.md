## Key Concepts

### Device-Bound Hard Lock
- Device UUID stored in `localStorage`
- First device binds successfully
- Second device gets 409 error (hard lock, cannot login)
- Only admin can unlock (Phase 9)
- **See:** `src/routes/api/bind-device/+server.ts`, ANTITHEFT_DOCTRINE_V1.md Section 5

### Premium Content Gate
- Single gate in `src/routes/premium/+layout.server.ts`
- Checks: session exists, not expired, subscription active, device matches
- Redirects to `/login` if any check fails (server-side, no flash)
- **See:** `src/routes/premium/+layout.server.ts`, ANTITHEFT_DOCTRINE_V1.md Section 5.4

### Offline PWA
- Service worker generated by Workbox (not hand-written)
- Cache-first for static content (questions, fonts)
- Network-first for dynamic content (premium hub)
- Never cache auth endpoints
- **See:** `vite.config.ts`, ANTITHEFT_DOCTRINE_V1.md Section 6

## Common Tasks

### Set Up for Local Development
1. Read [SETUP.md](./SETUP.md)
2. Create Supabase project
3. Copy credentials to `.env.local`
4. Run migration (0001_init.sql)
5. `npm install && npm run dev`

### Add a New Route
1. Create folder: `src/routes/new-route/`
2. Add `+page.svelte` (or `+page.server.ts` if data fetching needed)
3. SvelteKit automatically routes it

### Add a New Component
1. Create: `src/lib/components/MyComponent.svelte`
2. Import in any page: `import MyComponent from '$lib/components/MyComponent.svelte'`

### Modify Device Binding Logic
- File: `src/routes/api/bind-device/+server.ts`
- Keep the hard-lock behavior: reject second device (409 error)

### Modify Premium Gate
- File: `src/routes/premium/+layout.server.ts`
- This is the **only** place that enforces premium access
- Never add redundant checks elsewhere

### Add Content
1. Generate JSON via `build.py` (Phase 8)
2. Place in `static/content/science-biology.json`, etc.
3. Load via `src/lib/content/loader.ts`
